# Deploying

The site is static: no build step, no dependencies, only relative links. It works unchanged at a
subdomain root **or** under a subpath.

## Option A — `systems.joeko.net` (second Netlify site)

1. New site from the same repository.
2. **Base directory:** this folder. **Publish directory:** `.` **Build command:** empty.
3. Domain management → add `systems.joeko.net`. Netlify issues the certificate.
4. Add a CNAME for `systems` pointing at the Netlify site's `.netlify.app` hostname.

Independent deploys — a rebuild here can never break the portfolio build. Costs one extra site
slot and one DNS record.

## Option B — `joeko.net/systems` (subfolder of the portfolio)

Copy or symlink this folder to `systems/` inside the portfolio's publish directory. No second
site, no DNS change, no certificate. The library then redeploys whenever the portfolio does,
which is the trade-off.

If the portfolio's publish directory is generated by a build, add a step that copies this folder
into the output rather than committing it inside the generated directory.

## Either way

- Do **not** commit `tools/audit.html` expectations into CI; it is a manual harness that needs a
  local HTTP server (`python3 -m http.server 8899`), not `file://`.
- `tools/library-artifact.html` is the standalone catalogue published as a Claude Artifact. It is
  safe to deploy alongside the site, but the site's own `index.html` is the better entry point
  because it links through to the page templates.
- Rebuild before deploying: `python3 build.py all`.
