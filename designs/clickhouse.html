Why it is fast

Columnar, vectorised, compressed

Three decisions made at the storage layer that no amount of query tuning elsewhere can match.

Columnar storage

Only the columns a query touches are read from disk, which for wide analytical tables is most of the win.

Vectorised execution

Operations run over blocks of thousands of values, keeping the CPU pipeline full.

10× compression

Sorted columnar data compresses hard. Typical deployments store a tenth of the raw bytes.

Scales horizontally

Shard and replicate across nodes, with distributed queries planned automatically.

Speaks SQL

Ordinary SQL with analytical extensions. Your BI tool connects over the existing wire protocols.

Cloud or self-hosted

The same engine, managed by us or running on your own tin. Open source either way.

Questions

Is the open-source version crippled?

No. The managed service runs the same Apache 2.0 engine with no proprietary query features. You are paying for operations, not capability.

Can it replace my transactional database?

No, and it should not try. It is built for analytical scans over large tables, not high-concurrency single-row writes.

How does it compress so well?

Columnar layout plus sorting means adjacent values are similar, which general-purpose compressors exploit heavily. Ten-to-one is typical on real data.

What if we outgrow Cloud?

Export to Parquet and stand up your own cluster. The path is documented and customers do take it — that is the point of keeping the engine open.

Applying this system

  • Near-pure black with white type. There is no light-mode marketing surface in this system.
  • Electric yellow carries primary CTAs, the large stat-callout numbers, and full-bleed yellow bands — nothing else.
  • Cards sit barely lighter than the canvas. The colour-block contrast is deliberately subtle.
  • Huge yellow stat numbers in a heavy sans carry the credibility moment. That is the pattern, not a decorative flourish.
  • Radius is hierarchical: 8px buttons, 12px content cards, and pills only on tag badges.
